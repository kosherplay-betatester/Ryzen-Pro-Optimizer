Quick Start

What is Curve Optimizer?

Curve Optimizer (CO) is an AMD feature on Ryzen 5000 and newer that lets you shift each core's voltage/frequency curve. Negative offsets undervolt: the core uses less voltage at every clock — cooler, quieter, longer-lived, and often faster because boost behaviour is gated by thermals.

Each "point" of CO is roughly 3–5 millivolts. Values are temporary — they live in the SMU registers and reset on every reboot. When you find your sweet spot, write the values into your BIOS to make them permanent.

One-time BIOS prerequisite — PBO + CO must be enabled

Curve Optimizer is a sub-feature of Precision Boost Overdrive (PBO). Both must be enabled in your motherboard's BIOS once before any OS-level tool — including this one — can change CO at runtime. The app verifies every write by reading back; if the SMU silently ignores it (the classic signature of PBO/CO disabled in BIOS), a yellow setup card appears automatically with per-vendor menu paths (ASUS / MSI / Gigabyte / ASRock / Generic). Reboot into BIOS, enable PBO + Curve Optimizer once, save & exit. The next Apply will read-back-verify and you'll see "Applied ✓ (verified)" in the toast.

A word about the silicon lottery

Every CPU is unique. Two identical chips off the same shelf can have wildly different limits. And within one CPU, individual cores vary too — your best core might happily run at −30 while your weakest one crashes at −10. That's normal. Finding your chip's sweet spot is trial and error, not a failure on your end. Be patient, step in small increments, and the report (and the Smart Suggestions) will guide you.

Step 1: Pick how you want to set CO

All cores — single value applied to every core. Easiest, but limited by your weakest core.

Per-CCD — separate value per CCD (only shown on dual-CCD chips like 7950X, 7950X3D, 9950X). On X3D variants, CCD0 has the V-Cache and is more sensitive to undervolt; CCD1 typically tolerates deeper offsets.

Per-core — set every core individually. Most flexibility, biggest reward, longest tuning time.

Step 2: Set values and Apply

Start gentle — try −10 first. If stable, push further. Step in 5-point increments while finding the rough limit, then narrow to 2 or 1 as you approach the edge.

Clicking Apply opens a confirmation modal showing the exact offsets you're about to write, with three buttons:

  • 📸 Save profile & apply — auto-saves your current values as set-curve-optimizer-<timestamp> before writing, so you can roll back instantly.
  • Apply only — write without saving.
  • Cancel — don't write anything.

Click outside the modal (the dark backdrop) to cancel.

Step 3: Pick a stability test

Choose a stress test mode:

  • Manual test — runs your current CO values through CoreCycler. You decide what to do with the report.
  • Auto-Adjust — per-core walker. When a core errors, CoreCycler bumps that core's offset upward (less negative) and retries. Set the upper ceiling (e.g. 0) and the increment (1–5 points).
  • Smart Auto-Adjust (Pro) — bisection-based, telemetry-aware, learns across sessions. See "Smart Auto-Adjust" below.

Default is Prime95 SSE — the most thorough Curve Optimizer stress test for Ryzen. AVX2 and AVX512 stress different SIMD units but run hotter. Pick the cycle count: 1 cycle for a quick sanity check, 3+ cycles strongly recommended for a confident stability result.

Step 4: Watch it run

Several panels light up while a test runs:

  • 🎯 Live Curve Optimizer — reads the SMU every 3 seconds and shows what the chip is running with right now. Toggle between Summary / Per-CCD / Per-core views. Watch Auto-Adjust walk individual cores upward, or Smart Tune step CCD0 and CCD1 in unison during phase A.
  • 📊 Pro Dashboard — live charts of per-core clock, per-core voltage, temperature (Pkg + CCD0 + CCD1), package power, plus a V/F scatter and per-core heatmap. Click any core in a per-core chart legend to toggle that line; shift+click to solo it (hide all others); shift+click again to restore all.
  • 🛡 Safety Guard banner — live limit-checker active during Auto-Adjust and Smart Tune. Auto-aborts on sustained temp/voltage breaches or any WHEA event.
  • 🎬 Tune Theater — for Smart Auto-Adjust only. Shows progress %, per-scope ladder cards with bounds and probe counts, and a live narrative log of every step the algorithm takes.

Step 5: Read the report

When the test ends, the report shows pass/fail per core, peak temps and power, and Smart Suggestions for your next step.

  • PASSED — all cores survived. Consider pushing further or banking the values as a profile.
  • FAILED — one or more cores errored. The report tells you which core and the suggested dial-back amount.
  • INCOMPLETE — test was stopped before finishing. Partial info, no verdict.

The Esc panic button

If your system goes unstable, press Esc at any time (or click the red RESET CO button in the header). All cores instantly reset to zero offset. No confirmation, no delay. The handler now also stops any running test first (otherwise Smart Tune would silently clobber its own offsets mid-probe) and closes any open apply-confirmation modal.

If something crashed — automatic recovery prompts

The app drops a panic-revert breadcrumb on disk before every CO write, and Smart Tune persists its session state after every probe. If the previous session crashed (BSOD, hard hang, process kill), the next launch surfaces one or both of these prominent recovery prompts at the top of the page:

  • ⚠ Previous run crash detected — shows the time, the reason, and the CO values that were active at the crash. Revert to launch snapshot rolls back to the values active when the previous server started; Dismiss discards the breadcrumb.
  • ⏸ Smart Tune was paused — shows the mode and last-known status. Resume from last position picks back up from the next pending scope; the interrupted probe is recorded as a permanent crash data point in your CPU's history (so the algorithm never re-probes that value). Discard session starts fresh.

A pulsing orange badge appears in the header so you can see the recovery prompt is available even when scrolled away from the top. Click the badge to jump back to the prompt.

Settings reset on reboot

Anything you apply here is temporary — it lives in the SMU registers until you reboot. Your BIOS Curve Optimizer values return on every boot. Once you've found your sweet spot, write the values into your BIOS to make them permanent.

Shutdown behaviour is configurable

At the bottom of the page you'll find a Shutdown behavior card. The defaults are conservative on purpose: the only thing that stops the service by default is the terminal window (Ctrl+C or closing the cmd window). Two optional triggers:

  • Closing the browser tab/window — opt-in. Disabled by default because Chrome's memory-saver and RDP disconnects look like a closed tab and would otherwise kill the service mid-test. When enabled, the server reverts CO to launch values and shuts down after a 3-minute heartbeat silence.
  • Esc also stops the server — opt-in. Disabled by default so Esc is a pure panic-reset. When enabled, Esc both resets CO and tears down the server.

Your settings are saved in your browser (localStorage) and survive reloads.

Advanced

Smart Auto-Adjust (Pro)

A bisection-based, telemetry-aware, history-learning auto-tuner that replaces the linear "bump-and-retry" walk. Five Goal Modes:

  • Daily Driver (default) — per-CCD only. 30–60 min. Conservative +2 safety margin. The right choice if you want a stable everyday value with minimum probe budget.
  • Max Stable — per-CCD pass first, then per-core refinement. 3–6 h. Tighter margin (+1). Finds each core's individual edge.
  • Adaptive — per-CCD then per-core. Runs continuously for hours/days, re-verifying. Catches silicon drift over time.
  • Characterize — per-CCD then per-core, faster probes, no margin applied. Insight-only: maps each core's voltage/frequency behaviour without committing values.
  • Overclock — chases positive CO offsets to push boost clocks. Per-CCD then per-core. Uses negative margin (steps back toward neutral from the discovered edge).

Key behaviours:

  • V-Cache CCD awareness — auto-detects X3D parts and gives the V-Cache CCD tighter bounds. Probed first so failures happen fast on the more delicate silicon.
  • Cross-session learning — every probe result is written to runtime/tuner-history.jsonl. Future sessions seed the search from your CPU's known-stable and known-crash bounds. Crashes are permanent guard rails: the algorithm never re-probes a value that has previously crashed your specific chip — across reinstalls if you keep the history file.
  • Pre-tune snapshot — before Smart Tune (and Auto-Adjust) starts, your current CO is auto-saved as a profile named pre-smart-tune-<ts> (or pre-auto-adjust-<ts>). Load it back from the Profiles list if the tune lands somewhere worse than you started.
  • Safety margin — the final locked-in value is shifted away from the discovered edge by the mode's margin. The point of bisection is to find the edge; the point of the margin is to not sit there.
  • Resume after a crash — Smart Tune persists session state after every probe, so an interrupted session can be picked back up. The mid-probe value gets logged as ABORT_CRASH (worst class) so it becomes a permanent guard rail in your history.

Tune Theater (Smart Auto-Adjust live view)

Auto-opens above the Pro Dashboard when a Smart Tune starts. Shows:

  • Progress header — overall %, per-scope status pills, rough ETA.
  • "Currently" strip — what the algorithm is doing right now (e.g., "Probing CCD1 at CO=−22 · Prime95 SSE · 3m 12s in"), updated every second.
  • Per-scope ladder cards — bounds (floor..ceiling), live knownStable | knownUnstable window, probe count, locked value, 🔋 marker on V-Cache scopes.
  • Live narrative log — every probe start, every classification, every bound tighten, every history hit, every safety event, with icons. Pinnable autoscroll.

Auto-Adjust (CoreCycler's per-core walker)

Lets CoreCycler automatically bump CO values upward (less negative) when it sees errors during a run. You set starting values (read from current SMU state), an upper ceiling (e.g. 0), and an increment (1–5 points). CoreCycler walks each core until stable or the ceiling is reached, then moves on. The 🎯 Live Curve Optimizer panel shows the bumps in real time.

Pro Dashboard

Toggleable card with live charts (Chart.js, vendored offline):

  • Per-core clock chart — one line per physical core, rolling window.
  • Per-core voltage chart — one line per core, VID readings.
  • Temperature chart — package Tctl/Tdie + CCD0 + CCD1 (on dual-CCD parts).
  • Package power chart — wattage over time.
  • Boost map (V/F scatter) — voltage × clock per core at the current instant.
  • Stats grid — Pkg Temp / Power / Avg Clock / Avg VID / Hottest Core / Avg Load. Each tile shows min/avg/max and turns warn/danger when approaching or crossing your safety limits.
  • Per-core heatmap — live tile per physical core showing V / clock / load%, with a 🔋 marker on V-Cache cores.

Interactive legend on per-core charts: click a core (e.g. C7) to toggle that line on or off. Shift+click to solo it (hide every other core). Shift+click the solo'd item again to restore all. Hover tooltip shows every core's value at the cursor's time position.

Time window selector (60 s / 3 m / 10 m / 30 m) controls the rolling history range. Pause freezes live updates; Reset stats zeros the min/max counters; Export downloads the full history as JSON.

Per-CCD strategy for V-Cache chips (7800X3D, 7900X3D, 7950X3D, 9800X3D, 9900X3D, 9950X3D)

The V-Cache CCD is more sensitive to undervolt because the cache stack on top constrains voltage and thermals. Most users hit the wall between −15 and −20 on V-Cache CCDs. The non-cache CCD (on dual-CCD parts) usually tolerates much more — often −25 to −30. Always start gentler on the V-Cache CCD. Smart Auto-Adjust knows this and applies tighter bounds plus V-Cache-first probe ordering automatically.

Step-size strategy (manual tuning)

Start with 5-point increments. When you're a few points away from your suspected limit, switch to 2-point steps. Once you start seeing errors, step in 1 to find the exact edge. Then back off 2–3 points for safety margin. If you'd rather not do this by hand, Smart Auto-Adjust automates the whole process.

Safety Guard (auto-tune watchdog)

A live limit-checker that runs alongside any Auto-Adjust or Smart Auto-Adjust run. Configurable in the 🛡 Safety Guards card:

  • Max core temperature — default 95 °C (Zen 4/5 hard limit). Configurable 50–105 °C.
  • Max core VID — default 1.45 V (AMD spec for Zen 4/5 daily). Configurable 0.9–1.55 V.
  • WHEA delta — abort on any WHEA event during the run. Toggleable; default on.

Hysteresis: a single transient spike just warns; three consecutive samples over the limit trigger an abort. WHEA aborts fire immediately. On abort, the guard stops the test, reads current CO, steps every core back one increment toward neutral, writes the safer values (with a panic-revert breadcrumb first), and transitions to REPORTING with the abort reason logged. Optional audio beep on trip.

What WHEA events mean

WHEA (Windows Hardware Error Architecture) events are the OS-level signal that the CPU detected a corrected hardware error. They don't always crash your system but they mean something went wrong at the silicon level. The Bodyguard indicator in the header is always watching for them — when one fires, you get an immediate toast and (optional) audio beep. A WHEA event during a stress test is a clear signal to back off the CO offset.

Profile management

Profiles are saved as JSON in the profiles/ folder, tagged with your CPU model. They store mode + values + optional notes. Each profile row has four buttons:

  • Details — inline preview: mode, CPU, core/CCD count, saved date, notes, summary, and per-core CO values as colour-coded pills. See what's inside before you load.
  • Load — load the profile into the form without applying. Lets you see what would be applied and tweak before committing.
  • Apply — apply immediately to the SMU.
  • × — delete.

Profiles do not auto-apply at boot — that would be a security/foot-gun risk. To re-apply after reboot, launch the app and click Apply on the profile you want.

Reading the report

The verdict logic:

  • PASSED — all cores completed all iterations cleanly, no WHEA events.
  • FAILED — at least one core errored or a WHEA event fired.
  • INCOMPLETE — user stopped the test before completion. Partial data only.

Smart Suggestions include next-step recommendations tailored to your verdict, mode, and CPU type. They're suggestions — not rules. Use your judgment.

Troubleshooting

Browser shows "Curve Optimizer Not Supported" — your CPU is older than Zen 3 (pre-Ryzen 5000). CO doesn't exist on those.

Apply toast says "⚠ CO write was IGNORED by the SMU" — PBO/CO is disabled in BIOS. The yellow setup card auto-appears with per-vendor menu paths (ASUS / MSI / Gigabyte / ASRock / Generic). Reboot into BIOS, enable PBO + Curve Optimizer, save, return here.

"ryzen-smu-cli not found" — run Install.bat to fetch CoreCycler and the SMU CLI.

Sensors not showing — LibreHardwareMonitor stack may have failed to load. The launcher self-heals if the DLLs are missing or are the .NET 10 build (PowerShell 5.1 can't load .NET 10). If still broken, delete vendor/*.dll and re-run Install.bat — the net472 build pinned from NuGet will be re-fetched.

Test ends unexpectedly — the CoreCycler subprocess may have crashed. Verdict is INCOMPLETE; check CoreCycler's own log under corecycler/logs/.

Smart Tune session won't start — usually the state machine isn't in IDLE or REPORTING. Stop any running test first. Check runtime/server.log for the actual reason returned by /api/smart-tune/start.

"Previous run crash detected" or "Smart Tune was paused" banner — the previous session left a recovery breadcrumb. Resume or Revert as appropriate; both are safe.
